# Tetris + 2048 — Design Doc

**Date:** 2026-11-14
**Status:** approved — human said implement after write, no further questions; builder check: "nothing important left"

## Intent and why

Extend the Retro Minigames collection with two classic endless score games — **Tetris** and **2048** — using the existing registry so they appear on the menu beside Snake, Sudoku, and Bounce. No framework rework.

## Goals

- Two new game modules: `games/tetris.js`, `games/2048.js`.
- Registered like every other game: one import + one entry in `js/app.js`.
- Each game is a **single endless marathon**: one "level", high score only, no locks.
- Pure logic (board, pieces, merges) separated from `mount` so it is unit-testable with `node --test`.
- Keyboard + touch controls, consistent with existing games.
- Shared retro theme (existing CSS variables, new classes only).

## Non-goals / anti-goals

- No difficulty tiers, line-target "clears", or unlock progression for these two (user chose endless mode over tier levels).
- No `onCleared` calls — these games never finish a level.
- No hold piece, T-spin scoring, wall-kicks beyond a simple system, combo/level-up gravity curves, or 2048 undo/continue.
- No sound, no multiplayer, no build step, no new dependencies.
- No changes to the game contract in `js/app.js` or `test/registry.test.js`.

## Constraints

- Vanilla ES modules; must pass `node --test test/*.test.js`.
- Fit the playfield without page scroll (same `fit`-style sizing approach as Snake/Bounce).
- `levels` must be a non-empty array with numeric `id`s (registry test).
- `freeChoice: true` so the single Marathon entry is never locked (same as Sudoku).

## Approaches considered

1. **Difficulty tiers as levels** — Tetris gravity tiers with line targets; 2048 targets 256→2048. Reuses unlocks fully; slightly artificial for endless classics.
2. **Single endless mode** — one Marathon level each, `freeChoice: true`, high score only. ✅ **Chosen.** Truest to the classics; level select is a one-item list (acceptable — Sudoku already uses `freeChoice`).
3. **Loosen the registry** to allow games without `levels` — touches shell + tests for no gain. Rejected.

## Architecture (the decided how)

### Descriptor shape (both games)

```js
export default {
  id: 'tetris', // or '2048'
  name: 'Tetris',          // or '2048'
  icon: '🟦',              // builder picks fitting emoji
  blurb: '…',
  freeChoice: true,
  levels: [{ id: 1, label: 'Marathon' }],
  mount(root, options) { /* … */ return cleanup; },
};
```

- Score is **higher-is-better** (default — do not set `scoreIsLowerBetter`).
- Call `options.onScore(score)` whenever the score increases (same pattern as Snake/Bounce).
- Never call `options.onCleared`.
- `options.onExit()` on "back to levels" (shell already provides the Back button).

### Pure logic vs mount

Each module exports testable functions (mirror Snake’s style):

| Game | Suggested exports |
|------|-------------------|
| Tetris | `createGame()`, `step(state)` / gravity tick, `move(state, dir)`, `rotate(state)`, `hardDrop(state)` — exact names left to builder |
| 2048 | `createGame()`, `move(state, dir)` (slide+merge+spawn), `canMove(state)` |

`state` is a plain object (board array, current piece, score, dead flag). `mount` owns DOM, interval/rAF, key/touch listeners, HUD, overlay, and cleanup — no logic in listeners beyond calling pure functions and redrawing.

### Tetris rules (minimal classic)

- Board **10 × 20**.
- Seven tetrominoes (I O T S Z J L), each with fixed cell offsets; rotate by cycling those offsets (90° steps). Simple rotation is enough — no SRS wall-kick table required.
- Spawn at top center; gravity interval starts ~800 ms and may step faster as lines are cleared (builder’s call on exact curve; keep it simple).
- Lock piece on landing (blocked below); clear full rows; score += line-clear points (builder picks a simple table: e.g. 1/2/3/4 lines → 100/300/500/800).
- **Game over** when a newly spawned piece overlaps locked cells → overlay with Restart / Choose Level; report final score via `onScore`.
- Controls: ← → move, ↓ soft drop, ↑ or X rotate, Space hard drop (desktop); on-screen buttons and/or swipe on the board (touch). Reuse `.dpad` / `.btn` patterns where they fit; new classes only if needed.

### 2048 rules (standard)

- **4 × 4** board; empty cells start; spawn a tile after every successful move: **2 (90%) / 4 (10%)**.
- Arrow keys + swipe: slide all rows/columns, merge equal adjacent pairs once per move (left-to-right order per direction).
- Score += value of each merge.
- No moves possible (no empty cell and no adjacent equal pair) → game over overlay; final `onScore`.
- Win condition (reaching 2048) is **not** a hard stop — keep playing (endless). Optional subtle "2048!" toast is builder’s call; not required.

### Shell wiring

```js
// js/app.js
import tetris from '../games/tetris.js';
import g2048 from '../games/2048.js';
export const games = [snake, sudoku, bounce, tetris, g2048];
```

No other shell changes. Menu grid auto-shows the new cards.

### CSS

Append to `css/style.css` (reuse `--bg --panel --neon --neon-dim --text`):

- Tetris well: grid of cells (Snake-style `.cell` variants or a `.tetris-grid` + `.tetris-cell`), piece colors — a small fixed palette per tetromino is fine.
- 2048: `.g2048-grid` / `.g2048-cell` (4×4), per-value tile classes (2…2048+) with readable text contrast.
- Fit board to viewport like Snake (`fitGrid` + `cellSizeFor`-style math); no page scroll while a game is open (existing `body:has(> #app > .game)` rule).

Builder-check calls (accepted):

- Tetris gets Snake-style pause (space / button) — mobile interruption must not kill the run.
- Tetris shows a next-piece preview (one field + a few cells).
- `sw.js` precache list gains `games/tetris.js` and `games/2048.js` (two lines; "no other shell changes" missed this).

### Tests

New files: `test/tetris.test.js`, `test/2048.test.js` — pure logic only (no DOM), node:test + assert, following `test/snake.test.js`:

**2048 (minimum):**

- slide left merges pairs once (`2 2 4` → `4 4`, not `8`)
- merge does not chain in one move (`2 2 2 2` → `4 4`)
- no-op move does not spawn a tile
- successful move spawns exactly one tile (2 or 4) on an empty cell
- full board with no adjacent equals → `canMove` false

**Tetris (minimum):**

- piece blocked below lands / locks at expected row
- full row clears and rows above shift down; score increases
- spawn overlap → dead
- rotate keeps piece in bounds or is rejected (pick one rule and test it)

`test/registry.test.js` already iterates `games` — both new descriptors must satisfy it (it will pick them up automatically).

## Shortcut / known limits

- `shortcut:` endless-only — no difficulty tiers or unlocks for Tetris/2048; when to upgrade: if users ask for progression, add levels without changing the descriptor contract (same `levels` array shape).
- `shortcut:` simple tetromino rotation without wall-kicks; when to upgrade: pieces clipping awkwardly near walls — then add a small kick list, still pure-function.
